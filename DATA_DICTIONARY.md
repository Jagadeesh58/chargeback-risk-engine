# Data Dictionary

Every column in `train.csv` / `dev.csv` / `test.csv`, matching the fields
defined in `models.py` (`Dispute` dataclass) and `config.py`.

## Core fields

| Field | Type | Description |
|---|---|---|
| `dispute_id` | str | Unique ID for this dispute, format `D000000` |
| `payment_id` | str | ID of the underlying payment, format `pay_########` |
| `reason_code` | str | One of the 4 reason categories (see below) |
| `amount` | float | Disputed amount, generated uniformly between 300 and 8000 |
| `respond_by` | date (ISO string) | Deadline by which evidence must be submitted |
| `would_win` | bool | **Label.** Whether the dispute would be won if contested. Generated by `hidden_truth.py` from a hidden variable, NOT derivable from a simple formula over the evidence fields below — see `MISTAKES.md` and `verify_no_leakage.py` for the empirical leakage check. This field is present in training/eval CSVs only; a real scorer at inference time would never receive it. |

## Reason codes

| `reason_code` value | Meaning |
|---|---|
| `item_not_received` | Customer claims the item never arrived |
| `item_not_as_described` | Customer claims the item didn't match its description |
| `unauthorized_transaction` | Customer claims they didn't authorize the charge |
| `duplicate_charge` | Customer claims they were charged more than once |

## Evidence fields

All evidence fields are `bool | None`: `True` = confirmed present,
`False` = confirmed absent, `None` = unknown / not collected for this
dispute (`None` is NOT the same as `False` — see `MISTAKES.md` for why
that distinction matters).

Each field is only **relevant** to specific reason code(s), per
`config.RELEVANT_EVIDENCE_BY_REASON`. For a dispute filed under a
different reason code, the field still has a value in the CSV (the
generator fills every field for every row) but that value carries no
real signal for that dispute's outcome and must not influence its score
(`scorer.py` enforces this structurally).

| Field | Relevant to |
|---|---|
| `has_tracking_number` | `item_not_received` |
| `has_delivery_confirmation` | `item_not_received` |
| `has_signature_confirmation` | `item_not_received` |
| `has_product_photos` | `item_not_as_described` |
| `has_item_description_match` | `item_not_as_described` |
| `has_return_communication` | `item_not_as_described` |
| `has_avs_match` | `unauthorized_transaction` |
| `has_cvv_match` | `unauthorized_transaction` |
| `has_device_fingerprint_match` | `unauthorized_transaction` |
| `has_duplicate_transaction_proof` | `duplicate_charge` |
| `has_refund_already_issued` | `duplicate_charge` |

## Generation parameters (from `hidden_truth.py`)

These control the synthetic generator and are documented here for
reproducibility, not stored per-row in the CSV:

- `HIDDEN_LEGIT_BASE_RATE = 0.60` — P(hidden seller legitimacy = True), never exposed to the scorer
- `WIN_RATE_IF_LEGIT = 0.82`, `WIN_RATE_IF_NOT_LEGIT = 0.18`
- `RELEVANT_FIELD_RATE_IF_LEGIT = 0.78`, `RELEVANT_FIELD_RATE_IF_NOT_LEGIT = 0.30`
- `IRRELEVANT_FIELD_RATE = 0.50` — irrelevant fields sampled independently of hidden legitimacy
- `CONTRADICTION_RATE = 0.08` — chance a relevant field is flipped against the hidden truth anyway
- `MISSINGNESS_RATE = 0.15` — chance any evidence field is `None` instead of `True`/`False`

## Empirically verified properties (from `verify_no_leakage.py`, run 2026-08-24)

- Overall `would_win` rate on train: 56.8%
- Reason-code-blind logistic regression AUC on dev: 0.586
- Best single evidence field AUC alone: 0.549 (well below the full-model AUC — no single field leaks the label)
- Reason-code-aware (per-reason submodel) AUC on dev: 0.691
